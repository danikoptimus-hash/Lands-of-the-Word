# Генерация картинок для игры

Ключ OpenAI хранится как сетевой секрет облачной среды Claude для `api.openai.com` — прокси подставляет его в запросы сам.
Переменная окружения не нужна, ключ в чат и репозиторий не попадает. Никогда не просить ключ у владельца (см. `CLAUDE.md`).

- `gen_img.py "<промт>" out.png [--size …] [--quality …] [--bg green|transparent|none] [--model gpt-image-2]` — одна картинка.
  Потоковый режим обязателен: прокси обрывает долгие запросы. Для спрайтов — `--bg green` + `key.py` (вырезка по хромакею: альфа по расстоянию до цвета углов, обрезка,
  уменьшение, webp); `--bg transparent` модель `gpt-image-2` не поддерживает (ответ «Transparent background is not supported»).
- `key.py src.png dst.webp <ширина>` — спрайт из картинки на зелёном фоне.
- Текстуры и пейзажи — `--bg none`, затем `PIL` → webp (`quality` 80–88).

Примеры промтов и что чем сделано — в `docs/LANDS_OF_THE_WORD.md` (замок, свеча, пергамент, кирпичи стены, остров
Каменоломни, значки наград, круглый город Бытия).

## Листы спрайтов — `sheet.py`

Несколько предметов за одну генерацию: попросить «лист спрайтов: шесть отдельных предметов сеткой три в ряд, два ряда,
не касаются друг друга и краёв», `--bg green --size 1536x1024`, затем разрезать по связным областям:

    python3 -I scripts/img-gen/sheet.py sheet.png apps/web/public/img/city-plan 96 donkey,camel,sheep,goat,dog,hen

Имена — по порядку слева направо, сверху вниз; третий аргумент — высота самого высокого спрайта, масштаб общий для
листа (относительные размеры сохраняются). Если областей не столько, сколько имён, скрипт печатает их рамки и выходит.

## Листы плиток — `tiles.py` (аватарки и гербы)

Набор готовых аватарок участников и гербов команд (решение владельца 14.11) сделан листами по девять плиток:
«лист из девяти плиток ровной сеткой три на три… между ними и по краям ровные белые промежутки… фон плитки
однотонный, свой у каждой плитки», `--bg none --size 1536x1536 --quality medium --api responses`. Размер у `gpt-image-2`
свободный (стороны кратны 16); лист 1536×1536 даёт плитки около 456 точек. Затем лист режется по белым промежуткам:

    python3 -I scripts/img-gen/tiles.py лист.png apps/web/public/img/avatars a 17 --skip 3,8

Каждая плитка сохраняется дважды: `a017.webp` (320) и `s/a017.webp` (128, для списков); `a` и номер — код картинки
(`packages/domain/src/avatars.ts`: «a001»…«a100» — аватарки, «g01»…«g50» — гербы в `img/crests`). `--skip` — плитки
листа, которые не берём.

Прокси рабочей среды обрывает запрос, если первые данные идут дольше 30 секунд («upstream request failed», ответ 502):
у тяжёлых листов первый промежуточный кадр в этот срок не укладывается. Тогда — `--api responses`: тот же рисунок
через Responses API, поток начинается сразу и не обрывается (лист 1536×1536 среднего качества — около 45 секунд).
Это не «кончились деньги»: при исчерпанном счёте API отвечает сразу — `insufficient_quota`, «You have no credits
remaining» (так было 14.11 посреди набора; счёт пополняется на platform.openai.com → Billing).

Гербы рисуются на белом листе («девять круглых гербов-медальонов… на чисто белом фоне… без теней»): `tiles.py` режет
точно по медальону, и герб сидит в круге ровно. Портретам и зверям помогает уточнение манеры («как масляная
живопись… полуреалистичные лица… фон внутри круга ровный… человек крупно по центру») — иначе листы выходят в разной манере.

Картинки набора отдаются с долгим кэшем (30 дней) и лежат в отдельном кэше приложения `lotw-avatars`: если заменить
картинку под прежним кодом, у тех, кто её уже видел, останется старая. В проде картинку под занятым кодом не менять —
новую класть под новым кодом (и расширять набор в `packages/domain/src/avatars.ts`).
